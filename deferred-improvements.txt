# Deferred Improvements — DesignDocMCP

This file records intentionally deferred improvements discovered during
real development and workflow validation.

Principles:

* Only real technical debt or validated architectural gaps
* No speculative roadmap ideas
* Remove item after implementation
* Priorities:

  * P1 = already affecting development quality
  * P2 = medium-term maintainability
  * P3 = future enhancement / ergonomics

---

## D1 — revert_to_event should evolve toward deterministic replay

**Priority**: P1

### Problem

Current `revert_to_event()` implementation uses:

* list truncation
* derived-state cleanup
* heuristic phase/status reconstruction

This is acceptable for v0.3 but becomes fragile as workflow complexity grows.

Future risks:

* nested workflow states
* multiple HUMAN_REVIEW branches
* replay-sensitive derived fields
* requirement hierarchy branching

### Why Deferred

Current behavior is stable and covered by tests.

Risk only grows when workflow complexity increases.

### Desired Direction

Move toward deterministic reconstruction:

```text
initial_state + replay(events)
```

instead of inferred state mutation.

### Suggested Fix

Introduce replay reconstruction engine:

1. reset session runtime state
2. replay events in order
3. rebuild derived state deterministically

### Risk

Medium

## D2 — revert_to_event does not truncate requirement_deltas

**Priority**: P1

### Problem

Loop 8 introduced `RequirementDelta`.

Current `revert_to_event()` does **not** truncate:

```text
session.requirement_deltas
```

Undo may leave requirement hierarchy inconsistent with event history.

### Why Deferred

Loop 8 explicitly excluded replay/undo redesign.

Currently low impact.

### Suggested Fix

Extend `revert_to_event()`:

```text
created_at <= target_event.created_at
```

truncate:

```text
requirement_deltas
```

Add rollback regression tests.

### Risk

Low

## D3 — API error contract uses HTTP 200 for failures

**Priority**: P1

### Problem

Current invalid-session behavior:

```json
200 + {"error":"..."}
```

Internally consistent but REST-inconsistent.

Expected:

```text
404 Not Found
```

or

```text
400 Bad Request
```

### Why Deferred

Changing behavior affects:

* clients
* tests
* backward compatibility

Loop 9 intentionally preserved compatibility.

### Suggested Fix

Standardize contract:

```text
invalid session → 404
validation failure → 400
unexpected exception → 500
```

Update API E2E tests.

### Risk

Medium

```text

```

to refined requirement submission tracking.

Completion should filter by current round.
